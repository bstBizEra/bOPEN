## Proposed project skills

| Skill | Trigger | Core behavior |
| --- | --- | --- |
| `bopen-plan-phase-work` | A phase requires decomposition | Resolve controls, build a DAG and issue bounded package contracts |
| `bopen-execute-work-package` | An authorized package is ready | Use isolated ownership, validate and emit a maker receipt |
| `bopen-review-exact-candidate` | A candidate requires independent review | Bind exact SHA/tree/digest, reproduce checks and verify references |
| `bopen-integrate-accepted-base` | Accepted artifacts must be combined | Import exact bytes, reconcile shared files and revalidate |
| `bopen-prepare-phase-gate` | Mandatory packages are technically accepted | Assemble evidence without claiming human authorization |
| `bopen-promote-evidence-to-skill` | Verified evidence suggests a reusable improvement | Generalize, forward-test, activate, measure or roll back |

## Mandatory instructions

Every candidate skill must preserve:

1. governed references resolve from one reviewable tree;
2. acceptance binds exact bytes, not titles or chat claims;
3. maker, checker, integrator and human authority remain distinct;
4. agent technical dispositions cannot create organizational authority;
5. missing reference, evidence, identity, validity or revocation fails closed;
6. learning requires verified evidence and fresh-agent forward tests;
7. skill acceptance and activation are separate decisions.

## Promotion plan

1. Map each skill to representative bOPEN tasks.
2. Build concise candidate `SKILL.md` files.
3. Add deterministic scripts only for repeated fragile checks.
4. Run positive, negative, boundary and regression tests using fresh Codex and
   Claude contexts.
5. Obtain independent exact-candidate review.
6. Record authorized activation.
7. Measure reproducibility, rework, context cost and control regressions.

This proposal intentionally does not place candidate files in the active
`.agents/skills` path.
