# ADR-0015 — Context tokens are ES256-signed with external key custody

**Status:** Proposed
**Date:** 2026-07-29
**Owner:** Security Authority
**Plan alias:** `ADR-P2-006` (BOPEN-IDP-001 §20)
**Phase:** Phase 2 — Membership & Enterprise Onboarding

> **Scope note.** This is bOPEN's ADR-0015 and is unrelated to any similarly numbered ADR in
> another programme.

## Context

Context access tokens are the credential every bOPEN API and satellite product will verify.
The signing decision determines who can *mint* tenant access, so it is the highest-blast-radius
choice in Phase 2. BOPEN-IDP-001 §12.4 requires asymmetric signing, external key custody,
published JWKS and rotation; none of that is decided yet.

## Decision drivers

- Verifiers will eventually include services outside the kernel's trust boundary. They must
  verify without holding a minting key.
- Key compromise must be recoverable by rotation, not by redeployment.
- Token size matters at 5-minute lifetimes and high switch volume.
- Algorithm confusion and `alg=none` are recurring JWT vulnerability classes.

## Options considered

1. **HS256 shared secret.** Smallest and fastest, but every verifier can mint tokens.
   Unacceptable once any service outside the kernel verifies. Rejected for production.
2. **RS256 (RSA-2048).** Universally supported; ~256-byte signatures, slow signing.
   Acceptable fallback if a dependency cannot handle EC.
3. **ES256 (ECDSA P-256).** Asymmetric, ~64-byte signatures, fast signing, universal library
   support. Selected.
4. **EdDSA (Ed25519).** Best raw properties and misuse-resistance, but thinner support across
   the language stack DEC-0004 selected. Revisit when support is uniform.

## Decision

Adopt option 3, ES256, with RS256 permitted only as a documented compatibility exception.

- **Algorithm allowlist is exactly `{ES256}`.** The verifier selects the algorithm from its
  own policy, never from the token header. `alg=none` is rejected unconditionally.
- **Key custody is external** — a KMS or HSM. Private keys never enter the repository,
  container images, environment files, CI logs or evidence bundles.
- **`kid` is mandatory** on every token; an unknown `kid` is rejected.
- A **versioned JWKS endpoint** publishes current and next public keys for verifier discovery.
- **Rotation**: a new key is published and trusted for verification before it is used for
  signing. The overlap must exceed maximum token lifetime plus clock skew; with 5-minute
  tokens the recommended signing-key lifetime is 90 days with a 24-hour overlap.
- **Compromise response** is revocation of the `kid` and immediate re-issue, documented in a
  runbook that does not yet exist.
- Validation order before context resolution: signature, algorithm, `kid`, issuer, audience,
  time window, then all mandatory claims. Tokens carry no email, name, group list, secret or
  provider assertion.

## Consequences

- **Implementation delta — this ADR is not implemented.** `platform_kernel/context_service.py`
  ships `DeterministicTestSigner`, a symmetric HMAC-SHA256 signer over a clearly marked
  non-production constant, and `ALLOWED_ALGORITHMS` is `{"HS256"}`. It exists so the
  acceptance suite can exercise algorithm, unknown-`kid`, tampering and expiry negative paths
  offline. **It must not reach any deployed path.** Ratifying this ADR requires an ES256
  signer, a KMS integration, a JWKS endpoint and a rotation runbook.
- The `TokenSigner` port already isolates the change; the validator's structural rules
  (mandatory claims, prohibited claims, `alg=none` rejection) carry over unchanged.
- A KMS becomes a hard availability dependency for context issuance. Signing failure must
  fail closed.
- Verifier libraries in every SDK language must be pinned and audited for algorithm-confusion
  handling.

## Security/data implications

- Removes the "any verifier can mint" property that makes option 1 unsafe.
- Bounds key-compromise blast radius to one `kid` and one rotation window.
- Until this ADR is implemented, **no environment may issue tokens to any real relying party.**

## Evidence

- `platform_kernel/context_service.py` — `TokenSigner`, `ContextTokenValidator`,
  `DeterministicTestSigner` (test boundary, documented).
- `tests/unit/test_context_switch.py` — `P2-T027` unknown key / `alg=none` / tampering.
- BOPEN-IDP-001 §12.2–§12.5; `docs/evidence/phase-2/provisional-decisions.md` §4.
