## Qualification boundary

This contract defines synthetic observations and projections for comparing two generic OIDC issuers. It does not select or approve an identity provider, configure a live connection, authenticate a real principal, create a runtime session, provision a tenant, authorize a release or freeze technology.

The sole external identity key is the exact issuer URI plus the exact, opaque, case-sensitive `subject`. Its digest uses RFC 8785 canonical JSON containing only `issuer` and `subject`. Issuers are compared without aliasing, case folding, path rewriting, trailing-slash normalization or discovery-based substitution.

Email address, email domain, organization/domain claims, groups, roles and other profile claims never link accounts and never establish a bOPEN tenant, membership, role, permission, entitlement or active context. A principal may project multiple external bindings only through explicit dual reauthentication, a separately approved recovery simulation or an exact-key migration observation. Collision or ambiguity denies.

## Synthetic contract chain

```text
Provider connection observation
-> authentication assertion observation
-> assurance evidence observation
-> external identity binding/account-link projection
-> principal-session projection
-> test and migration observations
```

Every record nests the QUAL-P0-00 qualification envelope, uses `qualification_only=true` and `synthetic_data_only=true`, carries deterministic seed/clock/simulator digest, audit and correlation references, and declares every downstream effect `NONE`.

No raw JWT, authorization code, PKCE verifier, state, nonce, refresh token, client secret, private key, real email address, personal data or production credential may enter the records. Only synthetic identifiers and SHA-256 evidence digests are permitted.

## Required denial coverage

The schema catalog requires cases for issuer mix-up and normalization, subject absence/case, same-email and same-subject cross-issuer separation, audience and authorized-party mismatch, `alg=none`, algorithm confusion, unknown/duplicate keys, invalid signatures, stale JWKS and rotation, state/nonce/PKCE failures, code/assertion replay, expired/future assertions, disabled providers, revoked bindings/sessions, inactive principals, link proof/CSRF/session-fixation failures, existing-key collision, unauthorized tenant claims, raw-secret leakage and migration ambiguity/collision/count/rollback failures.

An assertion denial produces no qualifying session projection. A principal that is suspended or deleted, a revoked binding, an insufficient assurance observation or an invalid account-link transition cannot yield a positive projection. All material observations carry one correlation ID and an expected audit-event reference.

## Explicit coverage limits

This package does not qualify SCIM provisioning, logout, deprovisioning, recovery operations, production cookie/session controls, database persistence, tenant switching, authorization, entitlements, RLS or the full bPro reference flow. Those capabilities require separately authorized subjects and evidence.

## Gate effect

All authority, PG-G0, identity-provider approval, production implementation, merge, release and runtime-activation effects remain false. A future A-subject -> B-execution -> C-independent-receipt chain can produce technical decision input only. DEC-0005 requires an attributable authority disposition outside this package.

## Extend-only change note

Reason: DEC-0005 needs reproducible provider-neutral identity evidence before any selection. Benefit of the prior phase: QUAL-P0-00 established offline catalogs, exact bindings and non-authority semantics. Expected outcome: two synthetic issuers can be compared without email-based merging, tenant-authority leakage or runtime side effects.
