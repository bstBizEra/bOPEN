# DEC-0014 — PG-P0 Completion Mechanism: Verifier + Human Apply; Exclude Tool-Performed Authoritative Apply

**Version:** 0.1
**Status:** Proposed
**Owner:** Architecture Authority
**Required concurrence:** Product and Engineering Authorities
**Work package:** GATE-P0-01 (Proposed; not accepted)
**Issued:** 2026-07-25
**Maker:** Claude (BST-SA Motor worker agent; `claude-opus-4-8`)

## Decision required

Fix the mechanism by which an approved PG-P0 completion transition (`ACTIVE → COMPLETE` in the
schedule register) is authoritatively applied:

1. **Adopt "verifier + human apply."** The durable, atomic ref update is the operator's **own
   single Git commit** that replaces the predecessor schedule-register bytes with the successor
   bytes; Git supplies the compare-and-swap (the commit parent is exactly the predecessor tree)
   and the atomic ref move. The independent transition **verifier** (`VERIFY-P0-01`, candidate
   `3946e946`) proves that commit is exactly the sanctioned transition — no agent performs the
   authoritative ref update.
2. **Exclude the tool-performed authoritative-apply adapter from the completion path.** The
   `ENCODER-P0-02` adapter (`tools/authoritative_phase_transition_store.py`, candidate
   `3c384c81`) constructs the successor commit and performs the authoritative expected-old
   `git update-ref` compare-and-swap itself. It is technically sound (32/32 focused tests;
   orphan-object safety; lost-CAS leaves the ref unchanged; signed surfaces unchanged) but it
   **crosses the human-apply boundary** and implements the execution-kernel design that was not
   selected. It must not be accepted or merged onto the completion path unless this decision is
   explicitly revised to Option 2 below.

## Options

1. **Verifier + human apply** — the human authors and commits the transition; the verifier proves
   it exact. Lightest; keeps the authoritative ref update a human act. *(Recommended.)*
2. **Tool-performed authoritative apply** — a tool (the `ENCODER-P0-02` adapter) reads the
   protected ref, builds the successor commit, and performs the expected-old ref CAS. Race-safe
   and mechanized, but the tool performs the authoritative ref move.
3. **Hybrid** — human-authored commit with a tool-assisted expected-old CAS pre-check; deferred
   as unnecessary for PG-P0.

## Recommendation

Option 1. It is boundary-clean (an agent never performs an authoritative ref update), minimises
new machinery, and is already independently verified: `VERIFY-P0-01` carries an independent
`ACCEPT_EXACT_SHA` and forbids any smuggled change (recompute-equals-proposed-successor),
enforcing all signature/authority/replay/invariant controls. This records the Architecture
Authority's stated direction in the 2026-07-25 review session ("VERIFY-P0-01 remains the valid
path"; "ENCODER-P0-02 must not be accepted or merged unless the Architecture Authority explicitly
revises the design to tool-performed apply").

  acceptance**; `ENCODER-P0-02` (`3c384c81`) remains **HOLD / ineligible** under Option 1.
- It changes no register and no signed surface. `PG-P0` remains `ACTIVE`; `PG-P1` remains
  `NOT_READY`; production implementation remains unauthorized.
- It does not resolve the separate scope-boundary decision (skeleton-boundary vs maturity-

- If Option 2 is ever selected, `ENCODER-P0-02` must receive a full independent exact-SHA review
  **by a checker who did not author the embedded verifier** (its `verify_phase_transition.py` is
  byte-identical to `VERIFY-P0-01`), plus the same human-gated acceptance.
